Scope
NFL player props only — no Moneyline, no Spread, no Totals, no defensive player props (tackles, sacks, INTs by a defender). That's a deliberate market-scope choice, not a data gap: this build fully tracks and scores defensive matchup quality — opponent-vs-position rank, EPA matchup edge, full team defensive stats — it just applies that to grading offensive player props (passing/rushing/receiving yards & TDs, receptions), not to a defender's own stat line or a game total.
Every factor this build computes
Matchup: EPA matchup edge (this offense vs. that defense), opponent-vs-position rank league-wide, combined offense-vs-offense scoring environment, line movement (magnitude-scaled), suspect-vs-stale-line-value data-quality gate.

Usage: snap%, target share, aDOT, red-zone share, goal-line share, two-minute-drill share.

Form: season / last-3 / last-10 / vs-opponent hit rate, checkable game by game.

Team offense & defense: EPA/play (both sides), success rate (both sides), pressure rate created/allowed, third/fourth-down rate (both sides), red-zone TD rate (both sides), pace, turnovers/game.

Environment: live weather forecast (wind/precip/temp) scored against the run/pass split (personal history first, positional read as fallback), historical wet/dry split, dome/outdoor + venue split cross-referenced against this week's actual roof, altitude flag.

Schedule: rest days, short week, travel distance, time-zone shift, primetime, neutral-site/international.

Injury/personnel: self injury status (hard override), O-line injury count, practice-participation trend (direction-scored — worsening penalizes, improving helps), starter-QB-change detection.

Speculative-only scouting take (no free in-season data source exists for this — clearly labeled, never scored): coverage-scheme/personnel tendencies, revenge-game and contract-year narrative.
Where the refresh actually runs
This site (Netlify) only serves the frontend, reads the latest saved snapshot, and — when you click "Refresh Now" — fires a GitHub Actions workflow. The full pipeline (odds, nflverse + play-by-play, weather, AI) runs on GitHub Actions, every 30 minutes plus on-demand, and saves its result straight to this site's Netlify Blobs store. See the project README for why it's on GitHub Actions rather than a Netlify Background Function (those require a paid Netlify Pro plan; GitHub Actions doesn't).

What actually costs Anthropic credits
Loading this page costs $0 — it only reads the latest saved snapshot from Netlify Blobs, no AI calls involved. Refreshes are manual-only (no schedule runs on its own): the only things that spend anything are clicking "Refresh Now" above, or manually dispatching the GitHub Actions workflow — each one runs the AI notes/scouting-takes/parlay-takes passes once. A hard daily cap (ANTHROPIC_DAILY_CAP_USD, default $5, set as a GitHub Actions secret/variable to change it) tracks real spend from the API's own token-usage response and skips all AI calls for the rest of the UTC day once it's reached — the spend total next to "Refresh Now" above shows where today stands. This is a best-effort cap, not a hard guarantee: it's checked between waves of concurrent AI calls, so a refresh already mid-flight when the cap is hit can overshoot by that one wave rather than cutting off mid-call.
Odds data budget (Rookie tier)
100,000 objects/month, 50 requests/minute, odds refreshed upstream about every 3 minutes. The GitHub Actions schedule runs every 30 minutes — well within budget — but object cost scales with events × markets per call, so keep an eye on actual usage in the SportsGameOdds dashboard for the first week or two and tune the cron schedule if needed.
